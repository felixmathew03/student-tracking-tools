The problem & opportunity

Why Synnefo Needs This

Synnefo’s operation spans student records, batches, academic sessions, attendance, assessments, internship work, placement preparation, finance, communication and documents. The platform connects these workflows without turning the product into an LMS.

Single longitudinal student record • Historical records survive batch/program changes • Role-specific operational workspaces • Automated notifications + traceable actions

Batch & program changes do not rewrite the past

History Is Sacred

BATCH TRANSFER

Batch A ends → Batch B begins → future sessions use B → historical A records remain

PROGRAM TRANSFER

Previous enrollment preserved → new enrollment created → new batch assigned → previous work reviewed

NO AUTOMATIC EQUIVALENCY

Same-named curriculum items across programs are not automatically equivalent

ARCHITECTURAL RULE

Current state is context; historical events remain permanent records

Consistency prevents friction

Naming & Code Standards

FILES

Use predictable names; group by feature/domain

VARIABLES

Descriptive camelCase; avoid ambiguous abbreviations

API

Resource-oriented URLs; consistent plural resources and status/error formats

DATABASE

Stable collection/field naming; explicit references; indexes documented

COMPONENTS

PascalCase for React components; feature-based organization

CONSTANTS

UPPER_SNAKE_CASE only for true constants/config keys

COMMENT RULE

Explain why, not what; document non-obvious business rules

Things easy to forget — but important

Operational Safeguards

SOFT DELETE / ARCHIVE

Programs and other historical master data should not be hard-deleted where the specification requires history

CONCURRENCY

Protect payments, transfers, permission edits and other sensitive mutations from conflicting updates

VALIDATION

Validate both client-side for UX and server-side for correctness

OBSERVABILITY

Structured logs, error tracking, health checks and request correlation

BACKUPS

Database backup/restore procedure and recovery expectations should be documented

DATA RETENTION

Define retention/access rules for sensitive records and uploaded documents

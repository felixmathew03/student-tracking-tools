Synnefo Platform: Sprint Plan

11 sprints (S0 to S10), each a vertical slice: schema → backend API → UI → something you can open and demo. Assumed 2-week sprints (about 22 weeks) for a small team; scale up or down to match your actual team. Tick a sprint when done to track progress.

How every module is built

1. Schema

Mongoose models, validators, indexes (from the schema page), seed data.

2. Backend

Routes, controller, service, Zod validation, permission check, audit hook, tests.

3. UI

Screens from the UI map, API hooks, loading/empty/error states, role guard.

4. Demo

Seeded sample data and a demo script, so each sprint ends with something visible.

Suggested stack

  • Frontend: React (Vite), React Router, TanStack Query, Tailwind, React Hook Form + Zod.
  • Backend: Node + Express, Mongoose, Zod, JWT in httpOnly cookies, role/permission middleware.
  • Services: S3 or Cloudflare R2 for files, email via SES/Resend/Nodemailer, scheduled jobs with node-cron (BullMQ if volume grows), PDF receipts and certificates.
  • Quality: Vitest/Jest + Supertest, ESLint, GitHub Actions, MongoDB Atlas (dev/staging/prod).
  • Folders: server/src/modules/<domain>/{model,routes,controller,service} and client/src/features/<domain>/{pages,components,api}, one folder per domain, matching the module groups.

Sprints

Definition of done (every sprint)

  • Models have indexes and unique constraints from the schema page; no derived values stored.
  • Every endpoint checks permissions; sensitive changes write to audit_logs with a reason.
  • Screens work on mobile for the student portal and desktop for staff, with empty, loading and error states.
  • Seed data and a short demo script exist; tests cover the main rules of the sprint.

Key risks to watch

  • Attendance and batch transfer rules (S2, S3): test that a transfer never changes old attendance and that cross-batch attendance works.
  • Money (S5): use Decimal128, make payments immutable, and test installment status calculations.
  • Email delivery (S6): set up the sending domain early (SPF/DKIM) since it can take days to verify.
  • Real data (S10): plan the import of existing students and fees well before go-live.
